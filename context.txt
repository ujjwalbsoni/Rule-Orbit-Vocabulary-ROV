Rule-Orbit Vocabulary (ROV)
Most BPE vocabularies spend a lot of slots on one string under a few rewrite rules:  the / the /  The / The, or walk / walks / walked / walking. Each variant costs an embedding row and a softmax logit, and the rare ones are undertrained. Pruning them makes sequences longer, which hurts compression. ROV instead keeps the segmentation identical and shrinks the ID space.

How it works
Train a normal tokenizer at a large size, say 128k.
Mine rewrite rules automatically. For token pairs that share a stem, compute the edit as a rule (strip_prefix, add_prefix, strip_suffix, add_suffix). A suffix or prefix index keeps this near-linear rather than O(V²).
python
pairs = defaultdict(list)
for a in vocab:
    for b in same_stem_candidates(a):      # via suffix/prefix index
        r = diff_rule(a, b)                # e.g. (“”,“”,“”,“ed”)
        if r: pairs[r].append((a, b))
rules = {r: p for r, p in pairs.items() if len(p) >= TAU and passes_gate(p)}
Apply a distributional gate. Keep a rule instance (a, b) only if the two tokens’ context vectors (for example PMI over the tokenizer corpus) are similar. This blocks spurious pairs like bed → be + d. Rules need minimum support (TAU), which lets +s, +ed, capitalize, and leading-space survive while one-off coincidences don’t.
Build orbits. Group tokens by union-find, pick the highest-frequency member as the base, and require every other member to be exactly one rule away from it. Anything that doesn’t fit stays its own base.
Encode as two streams. Run the normal tokenizer, then map each token to (base_id, rule_id), with rule_id = 0 meaning identity. Decoding applies the rule, so it is exactly lossless and the sequence length is unchanged.
Model side.
Input: E_base[b] + E_rule[r].
Output: a factorized head, p(b | h) · p(r | b, h).
Result: the embedding table and softmax shrink from V to roughly V_base + a few hundred rules.
Why it might beat plain pruning
The compression ratio (tokens per byte) is unchanged, because nothing gets re-split.
Variants share statistical strength, so a rare walked-style form inherits from walk.
Rules are mined, not hand-written, so agglutinative languages like Turkish and Finnish may benefit more than English.
Risks to test
Inference tooling: grammar-constrained decoding, logit processors, and speculative decoding assume a flat vocab. You can flatten lazily by computing p(b)·p(r|b) only for the top-k bases.
Irregular or non-productive forms can still leak through the gate, so tune the similarity threshold per language.
The factorized head adds a little compute, and p(r | b, h) is where quality could regress.
How I’d evaluate it
At matched compression ratio, compare bits-per-byte for two small LMs of equal total parameters, one flat-V and one ROV. Also compare rare-token loss and the fraction of parameters in embeddings and softmax. My guess is that 30–50% of an English-heavy vocab collapses into orbits, but that number needs measuring.

I haven’t checked the literature, so I can’t promise it’s unpublished. The closest relatives are Unigram pruning, Scaffold-BPE and Picky BPE, factored and hashed embeddings, and capitalization-marker schemes. The part I believe is less standard is the combination of automatic rule mining, the distributional gate, and a lossless tag stream.

The idea in plain words
A tokenizer is like a dictionary the AI uses to read and write. Every entry costs the AI memory and effort, and today these entries are wasteful:

walk, walks, walked, walking
the, The, THE
jump, jumps, jumped, jumping
That’s 10 separate entries, even though they’re really just 3 ideas (walk, the, jump) with small changes on top.

The trick
Instead of 10 entries, keep only the base word and add a small sticker that says how to change it:

Base word	Stickers
walk	none, +s, +ed, +ing
jump	none, +s, +ed, +ing
the	none, Capitalize, ALL CAPS
Now the dictionary holds 3 base words + 6 stickers = 9 things to learn, instead of 10. That looks like a tiny saving here, but the stickers are shared across every verb. With 20,000 verbs you’d still have only about 4 stickers, instead of 80,000 separate entries.

A sentence example
The sentence: “The dog walked.”

Old way: 3 tokens, The + dog + walked, each its own entry.
New way: still 3 tokens, but each is stored as a pair:
the + [Capitalize]
dog + [none]
walk + [+ed]
The sentence is the same length and decodes back to exactly the same text. Only the bookkeeping underneath changed.

Why it helps
Smaller brain. The AI needs far fewer entries to store and choose between.
Learning transfers. If the AI has seen walk a million times but walked only twice, the old way leaves it weak on walked. With stickers, it already knows walk, and it learned what +ed means from thousands of other verbs.
No longer sentences. Other ways of shrinking a vocabulary cut words into smaller pieces, which makes text longer and slower. This keeps the length the same.
The catch
It’s a new idea that hasn’t been tested, so I can’t promise it works. The AI now has to make two guesses per word (the base word, then the sticker), which adds some complexity. Irregular words like go / went don’t fit the sticker system, so they’d stay as their own entries.
